# Comunidad y guardianes

Propuestas abiertas, aprobación de guardianes y publicación desde main.

## Propósito

Cualquier persona puede leer, plantear preguntas, hacer un fork y proponer un pull request. Entrar en main exige la revisión del guardián configurado y verificaciones aprobadas. Proponer conocimiento no requiere permiso de escritura. Los ejemplos deben ser sintéticos o debidamente anonimizados.

## Guardianes iniciales

Guardián inicial: @ismael-lab. La identidad figura en CODEOWNERS. Con un único guardián y sin bypass, un pull request de su autoría necesita otro guardián autorizado para aprobarse; la autoaprobación no sustituye la revisión.

## Flujo de contribución

1. Abrir una issue con contexto y propuesta.
2. Editar Markdown en un fork o rama permitida.
3. Mantener idiomas y diagramas coherentes; explicar diferencias.
4. Abrir un pull request con razones, evidencias y límites.
5. El guardián revisa contenido y verificaciones; los cambios nuevos invalidan aprobaciones anteriores.
6. Un guardián integra el cambio aceptado en main protegida.
7. El sitio importa una versión fijada de main e indica la revisión de origen.

## Publicación del conocimiento

El sitio lee una copia versionada de main aprobada, nunca una rama de contribución. Los mantenedores ejecutan la sincronización y publicación documentadas. Leer, editar y publicar son pasos distintos. Una propuesta en un pull request no integra automáticamente el framework publicado.
