# Contributing to KDV Framework

Framework knowledge contributions belong in https://github.com/kolmeia-dataecosystems/kdv-framework. This repository accepts website code, navigation, accessibility and rendering improvements. Do not edit the generated knowledge snapshot as an editorial source.

We welcome accessible visual explanations and implementation improvements. You do not need to use a KDV product to contribute.

1. Open an issue describing the governance problem and context. Do not include personal data, secrets, client details or restricted DAMA/DCAM material.
2. Explain the proposed change, its intended effect, limitations and evidence. Identify whether it changes a principle, role, process, control, template or measure.
3. For code or content changes, fork the repository and work on a descriptive branch such as `codex/clarify-product-ownership`.
4. Update the source, keep EN/PT/ES editions aligned, rebuild, and run `npm run check`. Review desktop and mobile layouts for visual changes.
5. Submit a pull request describing the final behavior and validation. Link the issue when one exists.
6. Maintainers review conceptual accuracy, accessibility, licensing and practical usefulness. Accepted decisions are recorded in the PR and changelog.

Text, diagrams and templates contributed here are licensed under CC BY 4.0; code contributions are MIT. Submit only work you can license this way. Retain attribution and identify modified material. KDV and third-party trademarks are not licensed for independent endorsement or certification claims.

An illustrative example should state: context, accountable roles, decision, control, evidence, observed limitation and improvement. Mark synthetic scenarios clearly. An example is not a client testimonial.

Privacy/security reports should use the private contact in SECURITY.md instead of a public issue. No contributor activity implies certification by KDV or by the reference publishers.
